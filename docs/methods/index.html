Methods

Four rules the archive is kept to. They are in order because the work is.

01

Start from a claim.

Find where the system states what it will do — documentation, a comment, a check in the code — and treat that as the thing to be tested, not as fact.

02

Make the observation reproducible.

Record environment, versions, inputs, and steps while the result is fresh. Keep the evidence next to the claim it supports.

03

Separate what is shown from what is inferred.

State what the result establishes, which readings remain open, and where the investigation stops.

04

Publish after the fix.

Work in authorised environments, disclose to the vendor first, and wait for the patch to ship before anything goes public.
